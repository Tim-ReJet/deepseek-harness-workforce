# Agent Note: An empty `workforce-cell` profile and bundle boot before any Cell plugin exists

Status: implemented

English | [中文](2026-09-07-workforce-cell-profile-bundle.zh.md)

## Problem

ADR-006's disposable Cell DSH (one process answers one delegated task, enclosed from outside by nono, then exits) needs a real, named profile to boot under before `@workforce/execution-cell`'s Task/Gate/Loop runtime (CELL-002) or `@workforce/nono-bridge`'s ActionIntent-to-nono bridge (BRIDGE-001) exist. There was no `workforce-cell` entry in `PROFILE_TEMPLATES` and no `packages/bundle/workforce-cell` package for those later tasks to add a row to, mirroring the same gap `workforce-global` closed for the persistent host profile (DSH-001).

## Decision

`packages/bundle/workforce-cell` is a new bundle package, shaped exactly like `packages/bundle/workforce-global`'s manifest/tsconfig/README trio, but stacked over `@deepseek-ai/dsh-base` **and** `@deepseek-ai/dsh-headless` rather than `dsh-base` alone: a disposable Cell answers one task and exits, so the existing one-shot headless runner — not the persistent Web/HTTP host `dsh-web-app` provides — is the closest shipped shape to "Cell DSH essentials". It declares `"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`, peer-depends on `@deepseek-ai/cordis`, `@deepseek-ai/dsh-base`, and `@deepseek-ai/dsh-headless`, and adds no other dependency. Its `cordis.patch.yml` is a literal empty patch list (`[]`), with an inline comment naming the tasks that will populate it and warning against adding a `@workforce/*` dependency before the package that justifies it exists (an unresolvable workspace dependency breaks `pnpm install` repository-wide). `src/index.ts` carries no runtime API.

`PROFILE_TEMPLATES` in `packages/boot/app-boot/src/profile.ts` gains a `workforce-cell` entry: `bundles: ['@deepseek-ai/dsh-base', '@deepseek-ai/dsh-headless', '@deepseek-ai/dsh-workforce-cell']`, `patchReload: 'startup'` (a disposable Cell has no live-reload use case). `dsh --profile workforce-cell "task"` now auto-initializes and boots through the ordinary profile launcher, the same code path every shipped profile uses.

Following DSH-001's fix (`011f7fb958`) for the identical gap: naming the bundle in `PROFILE_TEMPLATES` is not sufficient for it to resolve. `resolveBundleDir` walks Node's real `resolve.paths()` from `apps/cli/package.json` (`INSTALL_ANCHOR` in `apps/cli/src/profile-boot.ts`), which only finds a package that is an actual dependency of that manifest and therefore linked into `apps/cli/node_modules`. `apps/cli/package.json` gains `"@deepseek-ai/dsh-workforce-cell": "workspace:^"` alongside every other shipped bundle; `tsconfig.base.json` (regenerated with `pnpm run gen-tsconfig-paths`), `apps/cli/tsconfig.json`, and `tsconfig.host.json` each gain the matching `paths` entry / project reference, mirroring `workforce-global`'s own registration. `packages/boot/app-boot/tests/profile.spec.ts`'s existing generic test — added by DSH-001, which resolves every `PROFILE_TEMPLATES` entry's bundles against the real `apps/cli/package.json` anchor — automatically covers the new entry with no further test-file change needed for that guard; a dedicated `toEqual` assertion for `PROFILE_TEMPLATES['workforce-cell']` was added alongside the existing per-template checks for the same reason `workforce-global` has one.

This bundle is deliberately nono-oblivious: ADR-006 encloses Cell DSH with nono as an external process boundary (PID 1 / supervisor), not a library the Cell links against. The bundle holds zero nono-specific code, no capability-manifest, permit, or credential logic (invariant 7 — "DSH-side permission UX cannot widen a Workforce permit"), and no signing code (invariant 4). It also does not wire `packages/mcp/mcp-client` in: a discoverable tool having zero mutation authority by default (plan 16) is a precondition later Cell tasks (TOOL-001, BRIDGE-001) must satisfy before any real tool reaches this profile.

The package carries `publishConfig: { access: 'public' }` and no `private` flag from the start, matching `dsh-base`/`dsh-headless`/`dsh-workforce-global` — `packages/bundle/workforce-cell` matches `scripts/check-workspace-constraints.ts`'s `releaseMemberDirectory` pattern (any `packages/<group>/<name>` outside `experimental/`), so starting from `private: true` would only repeat DSH-001's now-fixed mistake.

## Alternatives considered

- **Stack over `dsh-base` alone, like `workforce-global`**: rejected — a disposable Cell's whole reason to exist is answering one delegated task and exiting; `dsh-base` alone has no task-driving runner, and inventing one here would duplicate `dsh-headless`'s existing direct-Agent driver instead of reusing it.
- **Stack over `dsh-web-app`**: rejected per the packet objective — a disposable Cell has no persistent web/HTTP surface to serve; that layer's Host/HTTP/browser rows are exactly what ADR-006's per-task, exit-on-completion Cell does not need.
- **Boot the full composed `dsh-base` + `dsh-headless` (~80+ row) patch tree inside this package's own default-tier unit test**: rejected for the same reason `workforce-global`'s test suite defers it — that composition needs the installed CLI's own anchor and profile module-fallback resolution, which only the e2e tier (`apps/cli/tests/profiles/*`) exercises for any shipped profile today. The shipped test instead proves the patch document is the empty, parseable layer promised, `composeEntries` (the exact function the profile launcher calls) yields the `dsh-base` + `dsh-headless` row set unchanged with this bundle's rows appended, and a real Loader/Include mounts the bundle's actual patch file as a second layer with no thrown error.

## Consequences

- `dsh --profile workforce-cell` is a real, bootable profile with no Cell-owned plugin yet mounted; every later Cell task (CELL-002, BRIDGE-001) that populates this layer only edits `packages/bundle/workforce-cell/cordis.patch.yml` and adds its own dependency, never touching `PROFILE_TEMPLATES` again.
- `packages/boot/app-boot/tests/profile.spec.ts` gained an assertion block for `PROFILE_TEMPLATES['workforce-cell']`, and its real-anchor resolution test (from DSH-001) now also covers this entry without modification.
- `apps/cli/package.json`, `apps/cli/tsconfig.json`, `tsconfig.base.json`, and `tsconfig.host.json` each gained one entry for the new package, the same registration `workforce-global` already required; `packages/bundle/README.md`/`README.zh.md`'s package table and `scripts/verify-package-readme-model-experience.ts`'s allowlist each gained one row/entry, mirroring the parallel `workforce-global` bundle so a reviewer can diff the two.
- A full live boot of the real `dsh-base` + `dsh-headless` + `workforce-cell` composition (mounting every row through the actual profile module-fallback anchor) is deferred to the e2e tier, exercised the same way every other shipped profile's full boot already is — this bundle adds no new e2e test since the profile is currently empty and imports nothing beyond what `packages/boot/app-boot`'s own suite and the shipped `headless` e2e suite already cover.
